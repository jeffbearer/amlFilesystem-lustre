## Conflict 1: Ubuntu Distro Versioning

### Patch Details
- **Commit:** `e96c4222ed`
- **Title:** "To distinguish lustre-client-utils & lustre-client-module packages by Ubuntu distro versions"
- **Files:** `autoMakefile.am`, `debian/rules`
- **Purpose:** Adds oscode parameter to distinguish between Ubuntu versions (bionic/focal/jammy/noble) in package names

### Conflict Analysis
**Location:** `autoMakefile.am` around debian build targets

**Root Cause:** 2.17.0-RC1 added systemd-related exports in the same section:
```makefile
export SYSTEMD_UNIT_DIR=$(DESTDIR)$(systemdunitdir)
export SYSTEMD_PRESET_DIR=$(DESTDIR)$(systemdpresetdir)
```

The patch wanted to add:
```makefile
export VER=$$(sed -ne '1s/^lustre (\(.*\)).*/\1/p' debian/changelog);
```

### Resolution
**Strategy:** Keep both changes - they are independent and complementary.

**Final code:**
```makefile
export SYSTEMD_UNIT_DIR=$(DESTDIR)$(systemdunitdir)
export SYSTEMD_PRESET_DIR=$(DESTDIR)$(systemdpresetdir)
export VER=$$(sed -ne '1s/^lustre (\(.*\)).*/\1/p' debian/changelog);
```

**Rationale:** 
- Systemd exports are needed for 2.17.0's systemd support
- VER export is needed for Ubuntu version-specific package naming
- No semantic conflict - just context changes

**Risk:** LOW - Simple addition, both changes are independent

## Conflict 2: Disable Kmod Dependency

### Patch Details
- **Commit:** `ed973ab8c1`
- **Title:** "Add ability to disable dependency of userspace pkgs on kmod pkg"
- **Files:** `lustre.spec.in`
- **Purpose:** Adds `%bcond_with kmod_dep` to allow userspace packages to work with multiple kmod packages

### Conflict Analysis
**Location:** Multiple locations in `lustre.spec.in`:
1. BuildRoot section (~line 250)
2. lustre-devel requires (~line 500)  
3. lustre-tests requires (~line 530)

**Root Cause:** 2.17.0-RC1 refactored the spec file:
- Changed BuildRequires from `libyaml-devel` to `pkgconfig(yaml-0.1)`
- Added server-related Requires/Obsoletes/Provides
- Changed kmod requirements from exact version to version ranges

The patch adds conditional wrapping:
```spec
%if %{with kmod_dep}
Requires: %{requires_kmod_name} = %{requires_kmod_version}
%endif
```

### Resolution
**Strategy:** Wrap the refactored 2.17.0 requirements with kmod_dep conditionals

**Key decisions:**
1. **BuildRoot section:** Added kmod_dep check around the new Requires line
2. **Version matching:** Kept 2.17.0's version range logic (`>= %{requires_release_major_minor}`) inside kmod_dep check
3. **DKMS alternatives:** Preserved 2.17.0's DKMS-or-kmod logic:
   ```spec
   %if %{with kmod_dep}
   %if 0%{?suse_version} >= 1500 || 0%{?rhel} >= 8 || 0%{?fedora} >= 34
   Requires: (%{lustre_name}-dkms or %{requires_kmod_name} >= %{requires_release_major_minor})
   %else
   Requires: %{requires_kmod_name} >= %{requires_release_major_minor}
   %endif
   %endif
   ```

**Rationale:**
- Microsoft needs ability to disable kmod deps for multi-version deployments
- 2.17.0's DKMS support is desirable - wrap it rather than replace it
- Version ranges are better than exact matches - keep that improvement

**Risk:** LOW-MEDIUM - Spec file logic is complex but well-tested pattern

## Conflict 3: Call autogen.sh (RPMs)

### Patch Details
- **Commit:** `c901a76c70`
- **Title:** "Call autogen.sh when building rpms"
- **Files:** `lustre.spec.in`
- **Purpose:** Regenerate autotools files during RPM build

### Conflict Analysis
**Location:** `%prep` section in `lustre.spec.in`

**Root Cause:** 2.17.0-RC1 changed ChangeLog symlink names:
- **Patch expected:** `ChangeLog-lustre` and `ChangeLog-lnet`
- **2.17.0 has:** `ChangeLog-lustre-%{version}` and `ChangeLog-lnet-%{version}`

### Resolution
**Strategy:** Insert `sh ./autogen.sh` before the symlink creation, keep 2.17.0's versioned names

**Final code:**
```spec
%prep
%setup -qn lustre-%{version}
sh ./autogen.sh
ln lustre/ChangeLog ChangeLog-lustre-%{version}
ln lnet/ChangeLog ChangeLog-lnet-%{version}
```

**Rationale:**
- autogen.sh must run after %setup but before %build
- Versioned ChangeLog names are better for multi-version deployments
- Order matters: unpack → autogen → symlinks → build

**Risk:** LOW - Standard autogen.sh invocation

## Conflict 5: lustre_version_sha Parsing

### Patch Details
- **Commit:** `714bffbcdb`
- **Title:** "Add lustre_version_sha parsing to specfile to clean up package obsolescence"
- **Files:** `lustre.spec.in`
- **Purpose:** Allow package version to include git SHA for better version tracking

### Conflict Analysis
**Location:** Multiple locations:
1. Top of spec file - define `%package_version` variable
2. License/Group/Source lines
3. BuildRoot path
4. %setup and %build paths

**Root Cause:** 2.17.0-RC1 changed:
- License from "GPL" to "GPL-2.0-only AND LGPL-2.1-or-later" (SPDX format)
- Removed "Group: System Environment/Kernel" (deprecated in modern RPM)
- Kept "Source: lustre-%{version}.tar.gz" (patch changes to %{package_version})

### Resolution
**Strategy:** Add package_version logic at top, update all references, preserve 2.17.0 metadata

**Key changes:**

1. **Top of file - after %_kver definition:**
   ```spec
   %if %{defined lustre_version_sha}
       %global package_version %{lustre_version_sha}
   %else
       %global package_version lustre-%{version}
   %endif
   ```

2. **Package metadata:**
   ```spec
   License: GPL-2.0-only AND LGPL-2.1-or-later  # ← Keep 2.17.0 SPDX
   %if 0%{?suse_version} >= 1310
   Group: System/Kernel  # ← Keep for SUSE only
   %endif
   Source: %{package_version}.tar.gz  # ← Changed from lustre-%{version}
   ```

3. **BuildRoot:**
   ```spec
   BuildRoot: %{_tmppath}/%{package_version}-root
   ```

4. **%prep and %build:**
   ```spec
   %setup -qn %{package_version}
   cd $RPM_BUILD_DIR/%{package_version}
   ```

5. **Obsoletes logic:**
   ```spec
   %if %{defined lustre_version_sha}
   Provides: %{lustre_name}
   %else
   Provides: lustre-client = %{version}-%{release}
   %endif
   ```

**Rationale:**
- Microsoft builds from git with SHA in version: `2.15.8_33_gb2ec90b`
- package_version allows tar.gz name to match git checkout
- Conditional Provides prevents conflicts between SHA and non-SHA builds
- Modern SPDX license format is correct - keep it
- Group deprecated except for SUSE kernel packages

**Risk:** LOW - Well-tested pattern from 2.15/2.16 branches

## Patch Dropped: Socklnd Net Namespaces

### Patch Details
- **Commit:** `3f21d782f9` (from 2.16.1-client)
- **Title:** "Make socklnd pay attention to net namespaces of devices"
- **Files:** `lnet/klnds/socklnd/socklnd.c`
- **Purpose:** Fix AKS networking stability by checking net namespaces before processing device events

### Resolution
**Strategy:** PATCH DROPPED - No longer needed

**Reason:** 2.17.0-RC1 **ALREADY HAS THE FIX** with a superior implementation!

**Microsoft 2.16.1 patch approach:**
```c
if (!net_eq(dev_net(dev), ni->ni_net_ns) ||
    strcmp(ksi->ksni_name, dev->name)) {
    continue;
}
```

**2.17.0-RC1 upstream approach (KEPT):**
```c
struct net *dev_netns = dev_net(dev);  // At function start

/* Skip devices from a different namespace */
if (!net_eq(dev_netns, ni->ni_net_ns)) {
    CDEBUG(D_NET, "Skipping device %s from namespace %p (expected %p)\n",
           dev->name, dev_netns, ni->ni_net_ns);
    continue;
}

if (strcmp(ksi->ksni_name, dev->name))
    continue;
```

**Why 2.17.0's version is superior:**
1. **Variable caching:** Calls `dev_net(dev)` once, stores result
2. **Debug logging:** CDEBUG tracks namespace mismatches for troubleshooting
3. **Separate conditions:** Namespace and name checks separated for clarity
4. **Better readability:** Comments explain intent

**Changes Made:**
- Initially cherry-picked, created spacing conflicts
- Analyzed and determined 2.17.0 version is superior
- Dropped commit entirely using `git rebase --onto 3f21d782f9^ 3f21d782f9`
- No modification to socklnd.c needed - kept 2.17.0-RC1 version
- Confirmed 2.17.0 has identical functionality in both affected functions:
  - `ksocknal_handle_link_state_change()` 
  - `ksocknal_handle_inetaddr_change()`

**Testing note:** Still verify AKS stability with 2.17.0's implementation

**Risk:** NONE - Upstream's implementation is more robust than Microsoft's patch

## Conflict 6: Azure Linux 3 Support

### Patch Details
- **Commit:** `ba6eca37f8`
- **Title:** "feat: improve Azure Linux 3 Dockerfile and spec compatibility"
- **Files:** `contrib/Dockerfile-azurelinux3`, `lustre.spec.in`
- **Purpose:** Support building on Azure Linux 3 (Mariner)

### Conflict Analysis
**Location:** Two issues:

1. **Dockerfile:** `contrib/Dockerfile-azurelinux3` doesn't exist in 2.17.0-RC1
   - Conflict type: modify/delete
   - Patch adds it, HEAD doesn't have it

2. **Spec file:** Python bytecode compilation override
   - Location: `%global __os_install_post` definition
   - Root cause: Azure Linux has its own `__os_install_post` handling

### Resolution

#### Part 1: Dockerfile
**Strategy:** Accept incoming file - it's new

**Final action:**
```bash
git add contrib/Dockerfile-azurelinux3
```

**File contents:**
```dockerfile
FROM mcr.microsoft.com/azurelinux/base/core:3.0

RUN tdnf install -y \
    automake \
    libtool \
    make \
    gcc \
    kernel-devel \
    kernel-headers \
    kernel-rpm-macros \
    rpm-build \
    openssl-devel \
    # ... etc
```

#### Part 2: Spec file
**Original HEAD:**
```spec
%global __os_install_post %(echo '%{__os_install_post}' | sed -e 's!/usr/lib[^[:space:]]*/brp-python-bytecompile[[:space:]].*$!!g')
```

**Incoming patch:**
```spec
# Don't apply this to Azure Linux which has its own __os_install_post handling
%if ! 0%{?azurelinux}
%global __os_install_post %(echo '%{__os_install_post}' | sed -e 's!/usr/lib[^[:space:]]*/brp-python-bytecompile[[:space:]].*$!!g' | sed -e 's!/usr/lib[^[:space:]]*/brp-strip.*[[:space:]].*$!!g')
%endif
```

**Final code:**
```spec
# LUTF Turn off brp-python-precompile script as we don't want the python files
# to be compiled on installation
# Don't apply this to Azure Linux which has its own __os_install_post handling
%if ! 0%{?azurelinux}
%global __os_install_post %(echo '%{__os_install_post}' | sed -e 's!/usr/lib[^[:space:]]*/brp-python-bytecompile[[:space:]].*$!!g')
%endif
```

**Note:** Removed the second sed for `brp-strip` that was in incoming patch. Reasons:
1. Only in incoming patch, not in Microsoft's other branches
2. Strip removal not mentioned in commit message
3. Conservative approach - keep minimal changes

**Rationale:**
- Azure Linux 3's RPM macros conflict with manual `__os_install_post` override
- Check `azurelinux` variable set earlier in spec (line 40-42)
- Skip override for Azure Linux, let its macros handle it
- Other distros still need the override for LUTF compatibility

**Risk:** LOW - Isolated to Azure Linux 3 builds
